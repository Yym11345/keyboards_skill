# 抖音长尾词挖掘 · 使用与原理说明

> **抖音**搜索下拉联想长尾词挖掘工具 · v2.0

**免签名、免破解** —— 通过 Playwright 控制真实浏览器，把「核心词 + 字母 / 数字 / 中文后缀」
的探针（Probe）逐个敲进**抖音站内搜索框**，监听抖音搜索联想接口的返回，把下拉词连同
**触发它的那一个探针**一起抓下来，整理成可追溯的长尾词库。

**目标平台固定为抖音**（douyin.com），不针对其他平台。

---

## 一、它到底做了什么

抖音搜索框的联想下拉，是平台基于**抖音站内全量用户搜索行为**实时算出来的。
它比任何关键词工具都贴近真实需求——出现在抖音下拉里的词，是真的有人在抖音搜。

本工具做的事，就是**人为制造足够多的输入前缀**，逼出尽可能多的抖音联想分支：

| 探针类型 | 数量 | 示例 | 作用 |
|---|---|---|---|
| 裸核心词 | 1 | `发膜` | 拿到最高频的通用联想 |
| 字母探针 | 26 | `发膜 a` … `发膜 z` | 逼出英文/拼音开头的分支 |
| 数字探针 | 10 | `发膜 0` … `发膜 9` | 逼出型号、规格、年代分支 |
| 中文后缀 | 14 | `发膜 怎么` / `发膜推荐` / `发膜哪个好` | 逼出**交易意图**与**决策意图**分支 |

合计 51 个探针，覆盖「品类词 + 修饰词」两个维度。

带空格的变体（`发膜 怎么`）会被单独标注 —— 空格本身是一个强信号，
用户真的敲空格，通常意味着他要的是更具体的长问句。

## 二、运行逻辑

1. 打开浏览器，复用持久化 Profile（首次会新建，登录态得以保留）。
2. 跳转到目标站点首页，等待页面就绪。
3. 检查搜索框可用性。**若弹出登录或验证，脚本会等待 60 秒，请在此期间手动完成。**
4. 依次输入 51 个探针，每次输入后监听联想接口返回。
5. 每抓到一条联想，就带着「触发探针」「站内排名」「捕获时间」一起写入 SQLite。
6. 按触发探针分组，去重后导出 Excel 与 HTML。

### 数据模型

```sql
CREATE TABLE keyword_suggestions (
  suggestion   TEXT,     -- 抓到的抖音长尾词
  root_keyword TEXT,     -- 核心大词
  source_query TEXT,     -- 触发它的探针
  captured_at  TEXT,     -- ISO 时间戳
  rank         INTEGER,  -- 站内下拉排名（1 最高）
  PRIMARY KEY (root_keyword, source_query, suggestion)
);
```

主键设计成三元组，意味着：**同一个词被多个探针触发时，会留下多行**。
这正是本工具的价值所在 —— 一个词出现在 `发膜 怎么` 和 `发膜 推荐` 两个探针下，
说明它同时具备「怎么用」和「买哪个」两种意图，这是单探针工具拿不到的信息。

## 三、输出物

```
<out>/<核心词>/
├── <核心词>_长尾词库.xlsx
│   └── 列：最高推荐排名 / 核心大词 / 长尾精准词 / 触发搜索词 / 挖掘时间
└── <核心词>_长尾词报告.html
    └── 按触发探针分组的网格看板，带空格变体高亮
```

同一核心词重复挖掘会先清空该词的历史记录，保证是**当次全新覆盖**。
完整历史保留在 `<out>/keywords.db`，可跨次做对比分析。

## 四、环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | ≥ 18.0.0 | 推荐 20 / 22 LTS；**Node 22+ 可用内置 `node:sqlite`** |
| playwright | 1.60+ | **唯一必须安装的依赖**：`npm install playwright` |
| Google Chrome | 建议 | 复用真实登录态；无则自动回落 Playwright Chromium |

### 数据库与 Excel：自动双路径

| 能力 | 优先使用 | 自动回落 |
|---|---|---|
| SQLite | `better-sqlite3` | `node:sqlite`（Node 22+ 内置，零安装） |
| Excel | `exceljs` | 内置 xlsx 写入器（零依赖，直接产出 .xlsx） |

两者都自动探测，脚本启动时会打印实际使用的驱动，无需手工干预。
**`better-sqlite3` 与 `exceljs` 均列为 optionalDependencies —— 装不上完全不影响运行。**

### 实测记录

在 Node 22.22.2 + Playwright 1.63.0（Chromium 1243）环境下，
以「发膜」为核心词完整跑通 51 次探测，得到：

- **552 条记录 / 406 个去重长尾词 / 51 个触发探针**
- Excel（内置写入器路径）与 HTML 报告均正常产出
- 中途遇到一次页面崩溃，脚本自动重开页面并继续跑完剩余探针，未中断整轮

## 五、常见问题

| 现象 | 处理 |
|---|---|
| 缺少 playwright | `npm install playwright && npx playwright install chromium` |
| 找不到搜索框 | 抖音页面要求验证或登录；脚本会存 `miner_error.png` 供排查 |
| 探测没抓到词 | 脚本已内置「补敲空格」重试；仍为空说明抖音该次未触发联想接口 |
| 账号被要求验证 | 60 秒内手动完成；频繁触发请调大 `--delay` |
| better-sqlite3 装不上 | 无需处理 —— 自动回落内置 `node:sqlite`（Node 22+） |
| 页面中途崩溃 | 自动重开页面继续跑，日志出现「[恢复] 已重开页面」 |
| 想要更快 | 调小 `--delay`，但不低于 500ms，否则易被限流 |

## 六、合规边界

- 目标平台固定为**抖音**，仅采集其搜索框**公开返回**的联想词，
  不触碰用户主页、私信、评论、直播等非公开数据。
- 采集到的是**抖音的公开联想数据**，使用方须自行遵守抖音的用户协议与相关法规。
- 不得用于批量账号操作、恶意高频请求、绕过平台风控或数据转售。
- 请控制请求频率（默认 2 秒间隔），不要把探测间隔调到 200ms 以下。
